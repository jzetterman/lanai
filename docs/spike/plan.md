# Spike plan: Looking Glass software mode vs RDP

Governing spec: [spec.md](spec.md). Status: approved 2026-09-27.

## Files

- `spike/lgtest`: one Bash script with subcommands. Pins live at the top. The file ends
  with `if [[ ${BASH_SOURCE[0]} == "$0" ]]; then main "$@"; fi`, so tests can source its
  functions (an `&&` form makes `source` return 1 and breaks bats setup). Any awk that
  emits bytes runs with `LC_ALL=C`. Paths inside the script are absolute, built from the
  script's own directory; `$WORK` is `<script dir>/work`. `prepare` refuses unless
  `findmnt -no MAJ:MIN -T` gives the same device for `$WORK` and the source disk (a
  reflink needs one btrfs filesystem; subvolumes share the device).
- `spike/test/lgtest.bats`: bats tests. They load helpers with
  `bats_load_library bats-support` and `bats_load_library bats-assert` (installed under
  `/usr/lib/bats`). Temp dirs that must be on btrfs go under
  `$BATS_TEST_DIRNAME/../work/test-tmp/`.
- `spike/test/fixtures/`: real-format samples of `/proc/stat` and process command lines.
  Lock fixtures are built at test time (see `disk_locked`).
- `spike/assets/frame-index.html`: the frame-index animation (below).
- `spike/assets/scroll.ps1`: sends one key chord at a fixed rate to the focused window,
  after a start delay, e.g. `-Keys '{PGDN}' -Rate 10 -Seconds 10 -Delay 3`. It uses
  `Add-Type -AssemblyName System.Windows.Forms` and
  `[System.Windows.Forms.SendKeys]::SendWait` (`Send` throws in a console host). A
  `Stopwatch` schedules key i at `start + i/Rate` and sleeps only the time left, so the
  15.6 ms timer tick does not drift the rate. At the end it prints keys sent and the
  achieved rate. The scroll input then comes from inside the guest, identical in both
  transports. Run it as
  `powershell -ExecutionPolicy Bypass -File $HOME\Desktop\scroll.ps1 ...`, which
  bypasses Windows' default `Restricted` policy for that one process only.
- `spike/assets/rdp-60fps.reg`: sets `DWMFRAMEINTERVAL` (DWORD, 15 decimal) under
  `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations`, which lifts
  Windows' 30 fps cap on RDP sessions. It goes on the spike copy only; the real VM
  keeps Omarchy's default.
- `spike/assets/results-template.md`: copied to `docs/spike/results.md` at test time.
  A Runs table with measured values only (one row per task, mode and transport, with
  the transport that went first in each pair); a Ratings table (one row per mode and
  transport, the eight rating columns); CPU runs for tasks 4 and 5, one row per run,
  with the task-4 "Stats for nerds" resolution and codec check; a task-1 latency log;
  a `scroll.ps1` log (keys sent and achieved rate per run); a Security check table
  (step 6); a notes field (DNS form, held-key repeat under Looking Glass, and a manual
  touchpad scroll on the web page per transport: smooth, steppy or laggy); the
  decision checklist.
- `spike/work/` (gitignored): downloads, client build, VM copy, recordings, CSV output,
  test temp dirs.
- Runtime state in `$XDG_RUNTIME_DIR/lgtest/` (`$RUN` below): `ivshmem`, `spice.sock`,
  `qmp.sock`, `qemu.pid`, and passt's pid file.

**Scroll input.** Scrolling is driven from inside the guest by `scroll.ps1` (the
rated action). Wheel and touchpad scrolling travel different paths in each transport,
so each session also records one unrated observation: a manual touchpad scroll on the
web page, smooth, steppy or laggy.
Held keys are not used: the Looking Glass client ignores repeated key-downs while
FreeRDP forwards the host's repeats, so a held key is a different input in each
transport. Task 1 covers input latency. Record, as an observation, whether a held key
repeats under Looking Glass at all.

## Frame-index animation

- The page fills the viewport with one solid color per frame. It steps through the 8
  RGB-cube corners in fixed order (black, red, green, yellow, blue, magenta, cyan,
  white), one step per `requestAnimationFrame` callback.
- `?fps=30` steps on every second callback, not on a timer.
- Counting: for each recorded frame, average the crop region to one RGB value
  (`scale=1:1:flags=area`). If its largest channel distance to the nearest palette color
  is over 48, the frame is unreadable (a blended or torn frame): skip it and count it
  separately. Otherwise `delta = (idx - prev) mod 8`: 0 is a repeat, 1 is an advance,
  and k > 1 is an advance plus k - 1 skips. The first readable frame sets `prev` and is
  not an advance. A gap of exactly 8 steps reads as a repeat, so skips are a lower
  bound.
- Output, one line: `advances_per_s repeats skips unreadable duration_s`. Rate is
  advances divided by the clip duration from `ffprobe`.
- Crop coordinates are in recorded (physical) pixels. `lgtest snap <clip>` writes one
  frame as a PNG; pick a square well inside the viewer's content area.

## Testable functions (TDD)

Tests come first for the logic that guards the live disk or produces a decision number.
Host inputs are injectable: `LGTEST_PROC` (default `/proc`), `LGTEST_LOCKS` (default
`/proc/locks`) and `LGTEST_STAT` (default `/proc/stat`). Tests that need btrfs skip
unless `stat -f -c %T` on their temp dir says `btrfs`.

| Function | Behavior | Tests |
|---|---|---|
| `verify_sha256 <file> <sum>` | 0 on match; on mismatch, delete the file and fail | match; mismatch deletes and fails |
| `disk_locked <img>` | returns 2 if it cannot tell (locks file or image unreadable). Otherwise true if a line in `$LGTEST_LOCKS` has the image's inode and the device from `findmnt -no MAJ:MIN -T <img>` (trimmed, formatted `%02x:%02x`). On btrfs, `stat`'s device is the subvolume's and never matches `/proc/locks` | fixture lines built at test time from the temp image's `stat -c %i` and findmnt device, in the real `OFDLCK ADVISORY READ -1 00:1d:<ino> 100 101` format: match; no lock line; same inode, other device; an inode that is a prefix of another (123 vs 1234). **Live:** hold `flock` on a btrfs temp file and check against the real `/proc/locks` |
| `qemu_cmdlines` | print the command line of every process in `$LGTEST_PROC` whose argv[0] is `qemu-system-x86_64`, bare or with a path | matches bare `qemu-system-x86_64 -name Windows,process=windows` and a full path; ignores a shell whose arguments mention `qemu-system-x86_64` |
| `host_busy_seconds` | from the `cpu` line of `$LGTEST_STAT`: user + nice + system + irq + softirq, divided by `getconf CLK_TCK`. Guest time is already inside user and nice; steal is not host work | a real 10-field `cpu` line gives the known value |
| `baseline_median <csv> <seconds>` | median of the baseline rows whose length matches; fail if there are none | odd count; even count (mean of the middle two); rows of other lengths ignored; no matching rows fails |
| `prepare_copy <src> <dst>` | refuse, with a message naming the reason, if `qemu_cmdlines` finds a QEMU, if `disk_locked`, or if `disk_locked` cannot tell (fail closed); refuse if `dst` exists; delete a stale `dst.tmp`; copy into `dst.tmp`: create `data.img`, set `+C` only if `lsattr` shows `C` on the source, then `cp --reflink=always`; plain `cp` for `windows.rom`, `windows.vars`, `windows.mac`; then `mv -T dst.tmp dst`. A trap removes `dst.tmp` on failure | "locked" and "QEMU running" fixtures each give their own refusal message; a missing locks file gives a "cannot check locks" refusal; refuses when `dst` exists; on btrfs with a source built as touch, `chattr +C`, write 1 MiB: the copy has the `C` flag and `filefrag -v` shows shared extents; a failed copy leaves no `dst` and no `dst.tmp`; a rerun after a failure succeeds |
| `frame_index_rate <clip> <w:h:x:y>` | `ffmpeg -i <clip> -fps_mode passthrough -vf crop=<w:h:x:y>,scale=1:1:flags=area -pix_fmt rgb24 -f rawvideo -`, then the counting rule above | ffmpeg-generated clips through libx264 yuv420p, each checked within ±1 advance/s: 60 steps/s at 60 fps (N frames give N − 1 advances); 30 steps/s at 60 fps (repeats); 60 steps/s with every 4th frame dropped (skips); one 50/50 blended frame (unreadable, no fake advance); a 30-then-60 fps variable-rate clip (no frames lost); a white border around the stepping center, cropped `8:8:4:4` (only the crop is read) |
| `vm_args <capture> <gw> <setup> <expose>` | `run`'s argument builder: from the capture, drop `-display`, `-vga`, `-monitor` and `-pidfile` with their values; turn the tap `-netdev` into passt on the capture's netdev id; rewrite `/storage/` to `$WORK/vm/`; add the display, SPICE, QMP and pid file flags below. Fail closed on a leftover container path (`/run/shm`, `/storage`) or a network listener (`-vnc`, `-gdb`, `-s`, `-incoming`, `-nic`, `-net`, `port=`, `tls-port=`, `vnc=`, `websocket=`, and `tcp:`, `telnet:`, `udp:` with or without a `mon:` prefix) | against a copy of the real capture: flags kept as captured, passt on `hostnet0`, paths rewritten, no container paths, no emulated display; `--setup` adds GTK and the setup disk; `--expose-loopback` drops only the loopback mapping; a leftover `/run/shm` or `/storage` path fails; each listener form fails; a `&` in the work path stays literal |

`run`, `client`, `rdp`, `stop`, `build`, `record` and `snap` are thin wrappers. The real
run tests them. `measure`, `snap` and `frames` also get argument tests (task 8's
default length, the task 4 baseline refusal, label rules, a missing clip), and `run`
gets one for its live-disk refusal (a hard link between the source and `work/vm`).

## Subcommands

- `fetch`: download the three pins to `work/dl/`, `verify_sha256` each, stop on any
  mismatch. Extract the source to `work/src/`. Fill `work/setup/` with the unzipped IDD
  installer, the agent MSI, `rdp-60fps.reg`, `scroll.ps1`, `frame-index.html` and
  `scroll.csv`.
- `build`: `cmake -S work/src/looking-glass-B7-826-236efcb1/client -B work/build -DENABLE_X11=no`,
  then build. Fail if the configure output says "disabling USB audio support".
  Result: `work/build/looking-glass-client`.
- `prepare`: `prepare_copy "${LGTEST_SOURCE:-$HOME/.windows}" work/vm`.
- `capture`: while the real `omarchy-windows-vm` runs, save `qemu_cmdlines` to
  `work/dockur-cmdline.txt`. Refuse unless exactly one QEMU runs. The command line
  holds no password.
- `run [--setup]`: refuse if `qemu_cmdlines` finds any QEMU (two 16 GiB VMs exhaust the
  host, and a second VM pollutes CPU numbers). Refuse if `work/vm/data.img` is the
  source disk itself (`-ef`). Clear stale files in `$RUN`. Start QEMU
  in the foreground with `TMPDIR=$RUN`, so passt's pid file lands there instead of
  `/tmp`. **The capture is authoritative:** start from `work/dockur-cmdline.txt` and
  change only what the spec allows (display, network, the RDP frame-rate setting, file
  paths). The flags below are the expected result; if the capture differs, follow the
  capture. `vm_args` does the rewrite. The real capture differs in small ways, and
  `run` follows it: the disk has `bootindex=3`, the netdev id is `hostnet0`, and
  `-enable-kvm`, a second `-rtc` and `-serial mon:stdio` stay. dockur's monitor socket
  is dropped, but `-serial mon:stdio` keeps HMP on the terminal that runs the VM
  (Ctrl-A x kills the VM).
  - `-nodefaults`, `-machine q35,accel=kvm,hpet=off,vmport=off,smm=off,graphics=off,dump-guest-core=off`,
    `-global kvm-pit.lost_tick_policy=discard`,
    `-global ICH9-LPC.disable_s3=1 -global ICH9-LPC.disable_s4=1`,
    `-fw_cfg name=opt/org.tianocore/UninstallMemAttrProtocol,string=y`,
    `-smbios type=1,serial=SystemSerialNumber` (dockur's placeholder, reused as-is)
  - `-cpu host,kvm=on,l3-cache=on,+hypervisor,migratable=no,-vmx,+invtsc,arch_capabilities=off,hv_passthrough,-hv-evmcs`
  - `-smp 6,sockets=1,dies=1,cores=6,threads=1`, `-m 16G` (fixed; no override),
    `-rtc base=localtime,clock=host,driftfix=slew`
  - pflash: `windows.rom` read-only, `windows.vars` writable
  - disk: an iothread, `virtio-scsi-pci` with `scsi-hd` (`rotation_rate=1`,
    `bootindex=1`), raw, `cache=none,aio=native,discard=unmap,detect-zeroes=on`
  - `virtio-rng-pci`, `qemu-xhci` (`p2`/`p3` as captured) with `usb-tablet`
  - network, IPv4 only like dockur's NAT:
    `GW=$(ip -4 route show default | awk '{print $3; exit}')`; fail with a clear message
    if it is empty (no IPv4 default route). Then
    `-netdev passt,id=hostnet0,ipv6=off,map-host-loopback=none,dns-forward=$GW,tcp-ports=127.0.0.1/13389:3389,udp-ports=127.0.0.1/13389:3389`
    (the id follows the capture) and the captured
    `-device virtio-net-pci,id=net0,netdev=hostnet0,romfile=,mac=<copied MAC>`.
    - `map-host-loopback=none` turns off the gateway-to-loopback mapping.
    - With it off, passt's default DNS setup drops the loopback resolver
      (`127.0.0.53`, with Tailscale behind it). `dns-forward=$GW` brings DNS back
      alone: the guest's DNS queries to the gateway address go to the host's first
      resolver (`dns-host` defaults to it); nothing else to that address reaches host
      loopback.
    - The RDP forward from `127.0.0.1` still works with the mapping off.
  - Looking Glass:
    `-object memory-backend-file,id=ivshmem,share=on,mem-path=$RUN/ivshmem,size=128M`
    `-device ivshmem-plain,memdev=ivshmem` (128 MiB fits 4K)
  - SPICE: `-spice unix=on,addr=$RUN/spice.sock,disable-ticketing=on`; vdagent
    (`virtio-serial-pci`, `-chardev spicevmc,id=vdagent,name=vdagent`,
    `-device virtserialport,chardev=vdagent,name=com.redhat.spice.0`); USB redirection for Looking Glass USB
    audio (`-chardev spicevmc,id=usbredir0,name=usbredir -device usb-redir,chardev=usbredir0`)
  - QMP on `$RUN/qmp.sock`, `-pidfile $RUN/qemu.pid`
  - `--setup` adds `-vga virtio -display gtk` and the setup disk, with an absolute path:
    `-drive if=none,id=setup,file=fat:$WORK/setup,format=raw,readonly=on -device usb-storage,drive=setup`.
    Without `--setup`: `-vga none -display none`.
  - `--expose-loopback` (step 6 positive control only): drop `map-host-loopback=none`.
- `client`: `work/build/looking-glass-client -f $RUN/ivshmem spice:host=$RUN/spice.sock spice:port=0 win:setGuestRes=yes`.
- `rdp`: `xfreerdp3` with the `RDP_ARGS` from the `omarchy-windows-vm` on `PATH`, minus
  `/u`, `/p` and `/v`, with `/v:127.0.0.1:13389`, the same `/scale` logic (no `/scale`
  if `hyprctl` or `jq` fails), and `KRB5_CONFIG=~/.config/windows/krb5.conf` (created
  with Omarchy's realm-less content if missing). `/title:Windows VM - Omarchy` comes
  from `RDP_ARGS`. The arguments go on the command line, not through `/args-from:stdin`:
  they hold no password, and stdin stays free for FreeRDP's prompts. FreeRDP prompts
  for the user name and password; the script never handles them.
- `baseline`: refuse if `qemu_cmdlines` finds any QEMU; append `60,<busy_seconds>` (the
  `host_busy_seconds` delta over 60 s) to `work/baseline.csv`. Test fixtures use the
  same `<length>,<busy_seconds>` format.
- `measure <label> --task <n> --transport <lg|rdp|rdp-real> --mode <fullscreen|tiled> --res <WxH> --scale <pct> --hz <n> [--seconds <n>]`:
  default 60 s, or 1800 s for task 8. `measure` counts down "3, 2, 1, go" before
  its window opens. It records `host_busy_seconds` before and after and appends a row
  to `work/results.csv` with the raw busy seconds, plus the idle-subtracted value when
  `baseline_median` has rows of that length. For tasks 4 and 5 (the CPU decision
  inputs) it refuses to start without baseline rows of the run's length (60 s by
  default). **Every task run happens
  inside `measure`**, so every run records CPU, resolution, scale and refresh (spec
  requirement 7). Tasks shorter than the window run inside it and the rest idles.
  Task 4: load the video paused at 1:00 and press play on "go", so the window covers
  the fixed 60 s segment. Task 8: the window covers the whole 30 minutes; check the
  unlock criteria inside it.
- `record <label> [seconds]`: wait 3 s (time to focus the viewer), then
  `timeout -k 10 -s INT <secs> gpu-screen-recorder -w HDMI-A-1 -f 120 -cursor no -o work/rec/<label>.mp4`
  (default 10 s). Treat `timeout`'s exit 124 as success. Recording at 120 fps against
  the 60 Hz panel turns timing misses into repeats; the counter check proves it.
  `--region WxH+X+Y` switches to `-w region -region WxH+X+Y`.
- `snap <label>`: write the middle frame of `work/rec/<label>.mp4` as
  `work/rec/<label>.png`.
- `frames <label> <w:h:x:y>`: print `frame_index_rate` for `work/rec/<label>.mp4`.
- Labels (`measure`, `record`, `snap`, `frames`) match `^[A-Za-z0-9][A-Za-z0-9._-]*$`.
  `snap` and `frames` say "run lgtest record <label> first" when the clip is missing.
- `stop`: over `$RUN/qmp.sock` with `socat`, send `qmp_capabilities`, then
  `system_powerdown`; wait for exit; delete `ivshmem`.

## Steps

1. **Tests first.** Write `lgtest.bats`, see each test fail, implement, see it pass.
   `shellcheck spike/lgtest` is clean.
2. `lgtest fetch && lgtest build`.
3. Start the real `omarchy-windows-vm` (after Office finishes installing), run
   `lgtest capture`, then stop it.
4. `lgtest prepare`, then `lgtest baseline` three times (no VM running).
5. `lgtest run --setup`. When Windows is up, connect with `lgtest rdp`. From the USB
   disk: install `looking-glass-idd-setup.exe` (include the IVSHMEM driver) and
   `spice-vdagent-x64-0.10.0.msi`, import `rdp-60fps.reg`, copy `scroll.ps1`,
   `frame-index.html` and `scroll.csv` to the desktop. In the IDD helper, set Default refresh to 60. Shut down.
6. Security check.
   - Pick the probe port: if `ss -ltn` shows CUPS on port 631 bound to loopback only,
     use 631. Otherwise start a temporary loopback-only listener
     (`python3 -m http.server --bind 127.0.0.1 18631`) and use its port for both
     controls; stop it afterwards.
   - Positive control: `lgtest run --expose-loopback`. From the guest,
     `Test-NetConnection -ComputerName <gateway> -Port <probe port>` succeeds (reaches
     the host listener). Stop.
   - `lgtest run`. From the guest, the same `Test-NetConnection` now fails. A web page loads,
     `Resolve-DnsName wikipedia.org` succeeds, and a Tailscale MagicDNS name resolves.
7. Counter check with the spike VM and `lgtest client` running: open
   `frame-index.html` natively on the host at the default rate and at `?fps=30`,
   `lgtest record`, `lgtest snap`, `lgtest frames`. Both must read within 10%. If not,
   retry with `lgtest record --region` around the animation. If that fails too, stop
   and report.
8. Copy `spike/assets/results-template.md` to `docs/spike/results.md`. Then the protocol,
   alternating which transport goes first per pair. **Per-pair checklist:**
   - Sign out of RDP before starting the Looking Glass client.
   - Looking Glass: focus its window and run `omarchy-hyprland-window-transparency-toggle`
     once (Omarchy's opacity rule only matches `xfreerdp`; the toggle acts on the focused
     window). Select "Looking Glass USB Audio" as the Windows output.
   - Set the Windows display scale to what RDP's logic gives (140 or 180 from the
     Hyprland scale, else 100).
   - Same window size and position for both viewers: fullscreen, or the same tile.
   - After each resize, read back what Windows actually uses (Settings, Display, and
     Advanced display): resolution, scale and refresh rate. Adjust until they match the
     other transport of the pair at 60 Hz, and pass the observed values to `measure`.
   - Run the task inside `lgtest measure` with the matching flags.
   - **Task 1 latency:** film at 240 fps with the key and the screen in one shot. Step
     through the clip frame by frame (mpv: `.` and `,`) and log, per keypress, the
     frames from key contact to glyph in `results.md`. Take the median per transport
     and mode.
9. Calibration: `lgtest stop` the spike VM first. Copy `frame-index.html`, `scroll.ps1`
   and `scroll.csv` into `~/Windows` (dockur's shared folder, which the real guest sees
   as a network share). Start the real `omarchy-windows-vm`, and in a normal session
   copy the three files from the share to the desktop. Never import `rdp-60fps.reg`
   there. Repeat the counter check with its RDP viewer running, then tasks 1-6 with
   `--transport rdp-real`. The real VM keeps its 30 fps RDP cap; the decision rule's
   "better of" handles it per measure.
10. Apply the decision rule in `results.md`.
11. Cleanup: delete `work/vm` and `$RUN`. Keep `work/results.csv`, `work/rec/` and
    `results.md`.

## Risks and fallbacks

- **Guest won't boot on the copied firmware.** Stop and bring it to John. Changing the
  firmware breaks the spec's parity rule, so it needs a spec decision first. (dockur
  booted this exact firmware on 2026-09-27, so this is unlikely.)
- **An RDP login takes over the console session**, so the IDD display goes blank while
  RDP is connected. Expected: run the transports one at a time.
- **Windows wants reactivation** after the hardware change. It doesn't matter for the
  test.
- **DNS fails even with `dns-forward=$GW`.** Use QEMU's `dns=` option with a public
  resolver, and record that MagicDNS names won't resolve (a finding for the plugin).
